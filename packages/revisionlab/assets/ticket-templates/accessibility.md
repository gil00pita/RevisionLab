# Accessibility issue

Organize the description with these Markdown headings:
## Barrier and affected users
Explain the reported accessibility barrier and supported user impact.
## Affected screens and elements
Include routes, selectors, saved comment locations, and screenshot references.
## Expected accessible behavior
State the measurable improvement. Include a WCAG criterion only when supported; never invent a contrast ratio or claim conformance.
## Verification
Describe appropriate automated checks and manual keyboard, screen-reader, or visual verification as applicable.

Write acceptanceCriteria as a checklist of verifiable accessible outcomes. Separate historical scan findings from current verified behavior.
